### 4.3 Включить проверку пароля для пользователя

### 4.5 Сменить пароль администратора
```
Меню → Пользователи → Сменить пароль администратора
Старый пароль: (пусто)
Новый пароль: Admin1!aB  (примерный — должен пройти все проверки)
Подтверждение: Admin1!aB

При вводе нового пароля появится список требований с ✅/❌.

### 4.6 Настройки подгруппы
```
Меню → Безопасность → Настройки
```
- Выбрать **ПГ-1** или **ПГ-2** (кнопки)

### 4.7 Сигнатура компьютера (только ПГ-2)

Меню → Безопасность → Сигнатура компьютера
```
Показывает параметры системы и хеш. Нажми **"Записать текущую сигнатуру"**.  
При следующем запуске — если запустить на другом компьютере — покажет предупреждение.

## ШАГ 8 — Вход по сертификату на флешке (ПГ-1) 🔑

> **Что это такое:** В режиме ПГ-1 пользователю можно включить аутентификацию по
> USB-сертификату. Сертификат — это JSON-файл `<имя>.cert` на флешке, содержащий
> SHA-256 хеш пароля пользователя. Программа читает файл с флешки и сравнивает
> хеш из него с хешем, хранящимся в зашифрованной базе `users.dat`.

### 8.1 Подготовка (в программе)

1. Войти как `ADMIN`
2. Зайти в `Меню → Безопасность → Настройки`
3. Убедиться что выбран режим **ПГ-1**
4. В поле **«Путь к USB-носителям»** указать точку монтирования флешки:
   - Linux: `/run/media/<твой_логин>/<имя_флешки>` или `/media/usb`
   - Пример: `/run/media/mordvamp/KINGSTON`
5. Нажать **Сохранить**

### 8.2 Создать сертификат на флешке

Сертификат — обычный текстовый JSON-файл. Создай его вручную в терминале:

```bash
# 1. Вычисли SHA-256 хеш пароля пользователя
#    Если пароль пустой (по умолчанию):
echo -n "" | sha256sum
# → e3b0c44298fc1c149afbf4c8996fb924...  (скопируй только хеш, без "  -")

#    Если пароль, например, "Qwerty1!":
echo -n "Qwerty1!" | sha256sum

# 2. Замени /run/media/mordvamp/KINGSTON на реальный путь к твоей флешке
#    Имя файла ОБЯЗАНО совпадать с именем пользователя + .cert
cat > /run/media/mordvamp/KINGSTON/student1.cert << 'EOF'
{"username":"student1","hash":"e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"}
EOF
```

> 💡 Хеш пустого пароля всегда одинаковый:  
> `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`

### 8.3 Что должно быть на флешке

```
/run/media/<логин>/<имя_флешки>/
└── student1.cert     ← имя файла = имя пользователя + .cert
```

Содержимое файла (строго такой формат):
```json
{"username":"student1","hash":"<sha256 хеш пароля>"}
```

### 8.4 Включить сертификат для пользователя (в коде)

Флаг `use_certificate` хранится в `src/model.rs`, строка 29.  
По умолчанию он `false`. Кнопки в UI для переключения пока нет.  
Чтобы включить, в функции `User::new()` (строка 51) поменяй:

```rust
// src/model.rs, fn User::new()
use_certificate: true,   // ← включить USB-аутентификацию
```

После этого пересобрать: `cargo run`.

### 8.5 Где в коде происходит чтение сертификата

📄 **Файл:** `src/storage.rs`

| Функция | Строки | Что делает |
|---------|--------|-----------|
| `cert_path_for_user(username, cert_drive)` | 124–126 | Строит путь: `<cert_drive>/<username>.cert` |
| `verify_certificate(username, cert_drive)` | 139–150 | Читает JSON, проверяет поле `"username"`, возвращает `"hash"` |

**Логика проверки при входе:**
```
1. Если user.use_certificate == true:
2.   cert_hash = verify_certificate(username, settings.cert_drive)
3.   Если cert_hash == user.password_hash → вход разрешён ✅
4.   Если файл не найден или хеш не совпадает → отказ ❌
```

### 8.6 Как проверить без флешки (имитация)

```bash
# Создать фейковую "флешку" в /tmp
mkdir -p /tmp/fake_usb

# Создать сертификат с хешем пустого пароля
cat > /tmp/fake_usb/student1.cert << 'EOF'
{"username":"student1","hash":"e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"}
EOF
```

В настройках программы указать путь: `/tmp/fake_usb`.

## ШАГ 9 — Где в коде задаются ограничения на пароль и какие они

### 9.1 ПГ-1 — требования к паролю

📄 **Файл:** `src/password.rs`, функция `check_pg1()`, строки 23–43

| # | Требование | Как проверяется в коде |
|---|------------|------------------------|
| 1 | **Длина ≥ min_len** (индивидуальная для каждого пользователя) | `password.len() >= min_len` |
| 2 | **Строчные буквы** (a–z, а–я) | `c.is_lowercase()` |
| 3 | **Прописные буквы** (A–Z, А–Я) | `c.is_uppercase()` |
| 4 | **Цифры** (0–9) | `c.is_ascii_digit()` |
| 5 | **Знаки препинания** (`! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ { \| } ~`) | `matches!(c, '!'|'"'|...)` |
| 6 | **Нет повторяющихся символов** (каждый символ — ровно 1 раз) | `HashSet::insert(c)` → false если символ уже был |

**Где хранится `min_len`:**  
`src/model.rs`, строка 27, поле `User::min_password_len`.  
По умолчанию = **6** (строки 39, 50).  
Администратор меняет через DragValue в таблице (`app.rs`, строки 276–282).

**Когда применяется:**  
Только если у пользователя `restrictions_enabled = true` (кнопка `±Огр.`).  
Проверка в `app.rs`: строки 459–462 (пароль администратора), 521–524 (пароль пользователя).

**Пример пароля ПГ-1:** `Abc1!def` — 8 знаков, строч., прописн., цифра, знак, все уникальные ✅

---

### 9.2 ПГ-2 — требования к паролю

📄 **Файл:** `src/password.rs`, функция `check_pg2()`, строки 59–85

| # | Требование | Как проверяется в коде |
|---|------------|------------------------|
| 1 | **Длина ≥ global_min_len** (глобальная для всех) | `password.len() >= global_min_len` |
| 2 | **Латинские буквы** (a–z, A–Z) | `c.is_ascii_alphabetic()` |
| 3 | **Символы кириллицы** (а–я, А–Я, ё, Ё) | `matches!(c as u32, 0x0410..=0x044F \| 0x0451 \| 0x0401)` |
| 4 | **Знаки арифм. операций** (`+`, `-`, `*`, `/`) | `matches!(c, '+' \| '-' \| '*' \| '/')` |
| 5 | **Нет подряд одинаковых символов** (`аа`, `11` — запрещено) | `.windows(2).all(\|w\| w[0] != w[1])` |
| 6 | **Пароль ≠ имя пользователя задом наперёд** | `password != username.chars().rev().collect::<String>()` |

**Где хранится `global_min_len`:**  
`src/model.rs`, строка 68, поле `Settings::global_min_password_len`.  
По умолчанию = **8** (строка 78).  
Меняется в `Меню → Безопасность → Настройки`.

**Пример пароля ПГ-2:** `Аa+бBc1-` — есть латиница, кириллица, арифм., нет повторов ✅

---

### 9.3 Схема потока проверки пароля

```
Пользователь вводит новый пароль
        │
        ▼
app.rs: password_checks(pass, user)    ← строки 97–107
        │
        ├─ Subgroup::PG1 ──► check_pg1(pass, user.min_password_len)
        │                     password.rs, строки 23–43
        │
        └─ Subgroup::PG2 ──► check_pg2(pass, username, settings.global_min_password_len)
                              password.rs, строки 59–85
                                    │
                                    ▼
                            Vec<Check> { label: String, passed: bool }
                                    │
                                    ▼
                    Отображается как ✅ / ❌ в диалоге смены пароля
                    Если restrictions_enabled && не все ✅ → сохранение отклонено
```

**Где включается/выключается `restrictions_enabled`:**  
Кнопка `±Огр.` в таблице → `app.rs`, строки 269–274.  
Поле хранится в `model.rs`, строка 25.
