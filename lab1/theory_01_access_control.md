## 📌 ТОП вопросов которые задают на защите

---

### ❓ 1. Что такое идентификация и аутентификация? В чём разница?

**Идентификация** — процесс установления *кто* обращается к системе (ввод логина).  
Сообщаешь системе свою личность. Система ищет тебя в базе.

**Аутентификация** — процесс *подтверждения* личности (ввод пароля).  
Доказываешь что ты действительно тот, за кого себя выдаёшь.

> В программе:
> - Идентификация: поиск имени в `users.dat`
> - Аутентификация: `SHA-256(введённый пароль) == stored_hash`

---

### ❓ 2. Что такое авторизация?

**Авторизация** — определение *прав доступа* после успешной аутентификации.

> В программе: если пользователь = ADMIN → полный доступ; иначе → только смена пароля.

Порядок: **Идентификация → Аутентификация → Авторизация**

---

### ❓ 3. Почему пароли хранятся в виде хеша, а не в открытом виде?

- Если файл `users.dat` утечёт — злоумышленник не получит пароли напрямую
- Хеш — **односторонняя** функция: из хеша нельзя восстановить пароль
- При проверке: `SHA-256(введённый) == stored_hash`
- Даже администратор базы не знает пароли пользователей

> **SHA-256**: детерминированная функция, дающая 256-бит (32 байта) вывод.  
> Любое изменение входных данных → полностью другой хеш (лавинный эффект).

---

### ❓ 4. Почему используется AES-256, а не просто SHA-256 для шифрования файла?

- SHA-256 — это **хеш-функция** (одностороннее преобразование), не шифр
- **AES-256** — симметричный блочный **шифр**: данные можно зашифровать И расшифровать
- Для хранения данных нужна обратимость → только шифр

---

### ❓ 5. Что такое CBC? Зачем нужен IV?

**CBC** (Cipher Block Chaining, режим сцепления блоков):
```
C_i = Encrypt(P_i XOR C_{i-1})
```
Каждый блок шифруется с учётом предыдущего шифроблока.

**Зачем IV** (Initialization Vector, вектор инициализации):
- При одинаковых данных без IV шифротекст всегда одинаковый → уязвимость
- IV — случайные 16 байт, разные при каждом шифровании
- С разными IV: одинаковые данные → разные шифротексты
- IV **не секретный**, хранится вместе с данными

---

### ❓ 6. Что такое диспетчер доступа?

Компонент СРД, который:
1. Получает запрос субъекта на доступ к объекту
2. Сверяется с базой полномочий
3. Принимает решение: **разрешить или отказать**
4. Регистрирует событие в журнале

> В программе: диспетчер — это проверка роли пользователя (ADMIN или обычный) при каждом действии.

---

### ❓ 7. Что происходит при 3 неверных попытках ввода пароля?

Программа завершает работу (`ctx.send_viewport_cmd(ViewportCommand::Close)`).  
Цель — защита от атаки перебором (brute force).

---

### ❓ 8. Что такое блокировка учётной записи и зачем она нужна?

Администратор может запретить вход конкретного пользователя.  
Причины: уволен, нарушения, временный запрет.  
При попытке входа: "Учётная запись заблокирована."  
Снять блокировку может только ADMIN.

---

### ❓ 9. Что такое сигнатура компьютера (ПГ-2)?

Уникальный отпечаток системы — SHA-256 от набора параметров:
- Имя пользователя ОС
- Имя компьютера (hostname)
- Корневой раздел
- Объём ОЗУ
- Тип и размер файловой системы

**Зачем**: обнаружение несанкционированного копирования.  
Если программу скопировать на другой компьютер — параметры изменятся → сигнатура не совпадёт → предупреждение.

---

### ❓ 10. Что такое USB-сертификат (ПГ-1)?

Способ аутентификации без ввода пароля.  
На USB-носителе хранится файл `username.cert` с:
```json
{ "username": "user1", "hash": "<sha256 пароля>" }
```
Программа читает файл с USB, проверяет имя и хеш.  
Параметры пользователя хранятся на носителе, а не в локальной БД.

---

### ❓ 11. Почему требование "нет повторяющихся символов" повышает безопасность?

Пароль из N уникальных символов перебирается сложнее:
- Из алфавита 95 символов можно составить 95^8 паролей длиной 8
- Но с повторами: некоторые пароли слабее (напр. `aaaaaaaa`)
- Запрет повторов: каждый символ несёт максимум энтропии

---

### ❓ 12. Что такое принцип минимальных привилегий?

Пользователь получает **только те права**, которые необходимы для его задач.  
> В программе: обычный пользователь видит только 2 пункта меню вместо полного набора.

---

### ❓ 13. Почему ADMIN — фиксированное имя, а не произвольное?

По заданию — упрощение. В реальных системах роль администратора назначается любому пользователю (RBAC — Role-Based Access Control). Наша реализация использует простейший MAC (Mandatory Access Control) с двумя уровнями.

---

### ❓ 14. Что такое четыре блока СРД?

| Блок | Функция |
|------|--------|
| Идентификация и аутентификация | Проверка: кто ты? |
| Диспетчер доступа | Что тебе можно делать? |
| Криптографическое преобразование | Шифрование хранимых/передаваемых данных |
| Очистка памяти | Безопасное уничтожение данных после работы |

---

### ❓ 15. Как протестировать что файл действительно зашифрован?

```bash
# Посмотреть содержимое файла
xxd target/debug/users.dat | head
# Вывод: бинарные данные, не читаемый JSON
```

Для сравнения — так выглядел бы незашифрованный файл:
```json
{ "users": [{ "username": "ADMIN", ... }] }
```
