### ❓ 1. Что такое симметричное и асимметричное шифрование? В чём разница?

**Симметричное шифрование** — один и тот же ключ используется для шифрования и расшифровки.

```
Encrypt(K, Plaintext)  → Ciphertext
Decrypt(K, Ciphertext) → Plaintext
```

> В программе: **AES-128** — симметричный алгоритм. Ключ 128 бит = 16 байт.

**Асимметричное шифрование** — два ключа: открытый (public) для шифрования, закрытый (private) для расшифровки.

| Характеристика | Симметричное | Асимметричное |
|---|---|---|
| Ключей | 1 | 2 (пара) |
| Скорость | Быстрое | Медленное |
| Примеры | AES, DES | RSA, ECC |
| Применение | Шифрование данных | Обмен ключами, подпись |

---

### ❓ 2. Что такое блочный шифр? Чем отличается от потокового?

**Блочный шифр** — шифрует данные фиксированными блоками (например, AES = 16 байт).
- Если данных меньше блока — нужен **паддинг**
- Если данных больше — делится на блоки

**Поточный шифр** — шифрует побайтно или побитно (например, RC4, ChaCha20).

> AES в режиме CTR или OFB превращается в **функциональный** поточный шифр.

---

### ❓ 3. Как работает AES? Какие операции выполняются?

AES-128: 10 раундов над блоком 4×4 байта (State).

Каждый раунд (кроме последнего):
1. **SubBytes** — замена каждого байта через S-Box (нелинейность)
2. **ShiftRows** — циклический сдвиг строк на 0, 1, 2, 3 позиции
3. **MixColumns** — умножение столбцов в поле GF(2⁸) (диффузия)
4. **AddRoundKey** — XOR блока с раундовым ключом

```
Для AES-128:
  - Ключ: 128 бит (16 байт)
  - Блок: 128 бит (16 байт)
  - Раундов: 10 (для 192 бит — 12, для 256 бит — 14)
```

> В коде: [`src/core/crypto/aes.rs`](file:///home/mordvamp/Projects/4kurs/TZI/lab3/src/core/crypto/aes.rs) —
> структура `AesCipher` с расписанием ключей и методами encrypt/decrypt блока.

### ❓ 4. Что такое S-Box и зачем он нужен?

**S-Box** (Substitution Box) — таблица замен 256 значений (0x00 → 0x63 и т.д.).

- Обеспечивает **нелинейность** — без нелинейности AES можно было бы взломать алгебраически
- Построен на основе мультипликативного обратного в GF(2⁸) + аффинное преобразование
- **Лавинный эффект**: изменение 1 бита входа → изменение ~половины бит выхода

---

### ❓ 5. Что такое режимы работы блочного шифра? Зачем нужны?

Шифр работает с блоком фиксированного размера (16 байт). Режим определяет **как обработать несколько блоков**.

| Режим | Формула шифрования | Параллелизм | Паддинг | Применение |
|---|---|---|---|---|
| **ECB** | `C_i = E(K, P_i)` | Да | Да | ❌ Не используй! |
| **CBC** | `C_i = E(K, P_i ⊕ C_{i-1})` | Расшифровка | Да | Файлы, TLS |
| **CFB** | `C_i = P_i ⊕ E(K, C_{i-1})` | Расшифровка | Нет | Потоки |
| **OFB** | `O_i = E(K, O_{i-1}); C_i = P_i ⊕ O_i` | Нет | Нет | Спутники |
| **CTR** | `C_i = P_i ⊕ E(K, Nonce||i)` | Да | Нет | TLS 1.3, AES-GCM |
| **GCM** | CTR + GHASH (MAC) | Да | Нет | TLS 1.3, HTTPS |

> **ECB — запрещён**, т.к. одинаковые блоки открытого текста → одинаковые блоки шифротекста.

### ❓ 6. Что такое IV и зачем он нужен?

**IV** (Initialization Vector, вектор инициализации) — случайные 16 байт, которые используются при шифровании первого блока.

**Зачем:**
- Без IV: `Encrypt(K, "Hello World")` → всегда одинаковый шифротекст
- С IV: каждый раз разный шифротекст, даже при одинаковых данных и ключе

```
CBC:  C_1 = Encrypt(K, P_1 ⊕ IV)   ← IV используется
CTR:  O_i = Encrypt(K, Nonce || i)  ← Nonce играет роль IV
```

> IV **не секрет** — хранится/передаётся открыто рядом с шифротекстом.
> IV **не повторяется** с одним ключом.

### ❓ 7. Что такое паддинг? Зачем нужен PKCS#7?

Блочный шифр требует данных кратных 16 байт. Если данных 13 байт — нужно добавить 3 байта паддинга.

**PKCS#7**: каждый байт паддинга = количество байт паддинга.

```
Данные 13 байт → добавляем 3 байта 0x03:
[d1 d2 ... d13 | 03 03 03]

Данные 16 байт → добавляем 16 байт 0x10:
[d1 d2 ... d16 | 10 10 ... 10]  ← всегда добавляем!
```

> При расшифровке: последний байт = количество байт паддинга → убираем их.

### ❓ 8. Что такое GCM? Чем отличается от обычного CBC?

**GCM** (Galois/Counter Mode) — это **AEAD** (Authenticated Encryption with Associated Data):
- Шифрует данные (CTR-режим)
- Одновременно вычисляет **тег аутентификации** (128 бит)

```
Вывод GCM = [Ciphertext || Authentication_Tag]
```

**CBC** — только шифрование, без аутентификации.  
**GCM** — шифрование + аутентификация в один проход.

> Если кто-то изменил зашифрованный файл — GCM обнаружит это при расшифровке. CBC — нет.

Используется в **TLS 1.3**, **HTTPS**, **SSH**.

### ❓ 9. Что такое SHA-256? Как работает?

**SHA-256** — криптографическая хеш-функция (FIPS 180-4).

```
SHA-256(любые данные) → 256 бит = 32 байта = 64 hex-символа
```

**Свойства:**
1. Детерминированность: одни данные → всегда один хеш
2. Лавинный эффект: 1 бит изменения → ~50% бит хеша изменится
3. Необратимость: из хеша нельзя получить данные
4. Устойчивость к коллизиям: нельзя найти два разных входа с одним хешем

**Как работает:**
- Данные разбиваются на блоки по 512 бит (64 байта)
- Применяется 64 раунда сжатия с 64 константами (`K[]`)
- Начальные значения `H[0..7]` — дробные части корней первых 8 простых чисел

```
Реализация: src/core/crypto/hash/sha256.rs
Struct Sha256 { hash: [u32; 8], buffer: [u8; 64], length: u64 }
```

### ❓ 10. Что такое HMAC? Чем отличается от обычного SHA-256?

**SHA-256(данные)** — хеш без ключа. Любой может проверить, но и подделать.

**HMAC** (Hash-based Message Authentication Code) — хеш **с секретным ключом**:

```
HMAC(K, M) = SHA-256( (K ⊕ opad) || SHA-256( (K ⊕ ipad) || M ) )
где: ipad = 0x36 × 64, opad = 0x5C × 64
```

**Назначение:** проверка подлинности сообщения.
- Без знания ключа K — невозможно вычислить правильный HMAC
- Используется в TLS, JWT, API-подписях

> В коде: [`src/core/crypto/mac/hmac.rs`](file:///home/mordvamp/Projects/4kurs/TZI/lab3/src/core/crypto/mac/hmac.rs)

### ❓ 11. Что такое CMAC? Чем отличается от HMAC?

**CMAC** (Cipher-based MAC) — тег аутентификации на основе **блочного шифра** (AES), а не хеша.

```
CMAC = последний блок CBC-шифрования (с дополнительными ключами K1/K2)
```

| | HMAC | CMAC |
|---|---|---|
| Основа | Хеш (SHA-256) | Блочный шифр (AES) |
| Скорость | Быстрее на CPU | Быстрее на аппаратных AES-акселераторах |
| Стандарт | RFC 2104 | NIST SP 800-38B |

---

### ❓ 12. Что такое PBKDF2? Зачем нужна функция формирования ключа?

**Проблема**: пароли короткие и предсказуемые. Нельзя напрямую использовать пароль как ключ AES.

**PBKDF2** (Password-Based Key Derivation Function 2, RFC 2898):

```
DK = PBKDF2(Password, Salt, Iterations, dkLen)
   = T_1 || T_2 || ...
   T_i = HMAC(Password, Salt || INT(i)) × Iterations
```

**Параметры:**
- `Salt` — случайные байты, защита от rainbow tables
- `Iterations` — количество итераций (10000–600000): чем больше, тем медленнее брутфорс
- `dkLen` — длина выходного ключа (например, 32 байта для AES-256)

> В коде: [`src/core/crypto/kdf.rs`](file:///home/mordvamp/Projects/4kurs/TZI/lab3/src/core/crypto/kdf.rs)

### ❓ 13. Что такое лавинный эффект? Почему он важен?

**Лавинный эффект** — изменение 1 бита входа меняет примерно 50% бит выхода.

Если бы эффекта не было:
```
Encrypt("Hello World", K) = "XYZXYZXYZ..."
Encrypt("Hello Worle", K) = "XYZXYZXYZ..."  ← отличие только в 1 символе выхода
```
→ атакующий мог бы восстановить данные посимвольно.

В AES лавинный эффект обеспечивают **MixColumns** + **ShiftRows** совместно.

### ❓ 14. Чем CTR отличается от CBC в плане надёжности?

| | CBC | CTR |
|---|---|---|
| Параллелизм шифрования | ❌ Нет (последовательно) | ✅ Полный |
| Параллелизм расшифровки | ✅ Да | ✅ Да |
| Паддинг | Нужен | Не нужен |
| Ошибка в 1 блоке | 2 блока повреждены | 1 блок повреждён |
| Случайный доступ | ❌ Нет | ✅ Да (прыгнуть к блоку N) |

> CTR используется в TLS 1.3 (в составе AES-GCM).

---

### ❓ 15. Что означает «реализация с нуля» SHA-256?

Библиотека `sha2` (крейт) даёт готовую SHA-256.
В **CryptoCore** SHA-256 реализована вручную на Rust — без использования внешних крейтов для самого алгоритма.

Это означает:
- Написаны функции `Ch`, `Maj`, `Σ0`, `Σ1`, `σ0`, `σ1` (из стандарта FIPS 180-4)
- Ручное управление буфером, паддингом (добавление бита 1, длины в конце)
- Константы `H[0..7]` и `K[0..63]` захардкожены из стандарта

Проверка корректности: тест-вектора NIST (известный вход → известный хеш).
