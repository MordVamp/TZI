## 2. Теоретическая часть

### 2.1 DRM (Digital Rights Management)

DRM — технология управления цифровыми правами, ограничивающая несанкционированное использование файлов. Основные механизмы:

| Механизм | Описание |
|---------|---------|
| Шифрование | Файл недоступен без ключа расшифровки |
| Привязка к устройству | Ключ зависит от параметров железа |
| Лицензионные ключи | Уникальный ключ для каждого пользователя/файла |
| Контроль доступа | Разрешение/запрет конкретных операций |

### 2.2 Алгоритм AES-256-CBC

**AES-256** (Advanced Encryption Standard, 256-bit key) — симметричный блочный шифр.  
**CBC** (Cipher Block Chaining) — режим сцепления блоков.

```
Шифрование одного блока (CBC):
  C_i = Encrypt_K(P_i XOR C_{i-1})
  C_0 = IV (случайный)

Расшифровка:
  P_i = Decrypt_K(C_i) XOR C_{i-1}
```

**Параметры**:
- Размер блока: 128 бит (16 байт)
- Размер ключа: 256 бит (32 байта)
- IV: 16 случайных байт, хранится вместе с шифротекстом

### 2.3 Аппаратный отпечаток (Hardware Fingerprint)

Уникальный идентификатор компьютера, вычисляемый как:

```
Fingerprint = SHA-256(username | hostname | ram_mb)
```

| Параметр | Источник |
|---------|---------|
| Имя пользователя ОС | `$USER` |
| Имя компьютера | `sysinfo::host_name()` |
| Объём ОЗУ (МБ) | `sysinfo::total_memory()` |

### 2.4 Генерация лицензионного ключа

```
Key = SHA-256(MASTER_SECRET | fingerprint | filename)
Formatted = XXXX-XXXX-XXXX-XXXX (первые 16 hex символов в upper case)
```

Ключ **привязан** к:
- Конкретному файлу (имя файла)
- Конкретному компьютеру (аппаратный отпечаток)

### 3.3 Вкладки интерфейса

#### 🔒 Шифрование
- Выбор файла (путь)
- Ввод пароля шифрования
- Результат: `<имя>.<расш>.drm` (base64 от AES-256-CBC)
- Автоматическая генерация и сохранение лицензионного ключа

#### 🔓 Защищённый просмотрщик
- Два метода доступа: **по паролю** или **по лицензионному ключу**
- Проверка ключа на соответствие файлу и отпечатку компьютера
- Отображение расшифрованного содержимого (текстовые файлы)

#### 🗝 Управление лицензиями
- Генерация ключа для любого файла
- Сохранение в `licenses/<имя>.license` (JSON)
- Кнопка копирования ключа в буфер обмена

#### 💻 Аппаратный отпечаток
- Отображение параметров, использованных для привязки
- Показ итогового SHA-256 хеша

## 4. Формат файлов

### 4.1 Зашифрованный файл (.drm)

```
Base64(
  [16 байт IV] || AES-256-CBC(исходные данные, ключ=SHA-256(пароль))
)
```

### 4.2 Файл лицензии (.license)

```json
{
  "key": "ABCD-1234-EF56-7890",
  "fingerprint": "<SHA-256 аппаратного отпечатка>",
  "filename": "document.txt.drm"
}
```

## 5. Алгоритм работы DRM-системы

```
ШИФРОВАНИЕ:
  read(file) → bytes
  key_32 = SHA-256(password)
  iv = random(16 bytes)
  ciphertext = AES-256-CBC(bytes, key_32, iv)
  write(file + ".drm") = Base64([iv || ciphertext])
  license_key = XXXX-XXXX-XXXX-XXXX (из SHA-256(secret|fp|filename))
  write("licenses/" + filename + ".license") = JSON{key, fp, filename}

РАСШИФРОВКА (по паролю):
  read(file.drm) → Base64 → [iv || ciphertext]
  key_32 = SHA-256(password)
  plaintext = AES-256-CBC-Decrypt([iv || ciphertext], key_32)
  display(plaintext)

РАСШИФРОВКА (по лицензии):
  read(file.drm)
  verify: SHA-256(secret|current_fp|filename) == license_key?
    → NO: "Ключ недействителен"
    → YES: decrypt с ключом SHA-256(secret|license_key)
```

В ходе лабораторной работы разработана собственная DRM-система защиты файлов на языке Rust. Реализованы:
