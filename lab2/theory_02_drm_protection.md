# 🎓 ТЕОРИЯ И ВОПРОСЫ НА ЗАЩИТЕ — Лаб 2: DRM-защита ПО

---

## 📌 ТОП вопросов которые задают на защите

---

### ❓ 1. Что такое DRM? Зачем это нужно?

**DRM** (Digital Rights Management) — управление цифровыми правами.  
Набор технологий, ограничивающих использование цифрового контента.

**Цели DRM:**
- Запрет несанкционированного копирования
- Привязка к устройству/пользователю
- Ограничение количества устройств
- Реализация триал-версий (ограниченный доступ)

**Примеры:** Steam (игры), Netflix (видео), Adobe (PDF), Windows (активация ОС)

---

### ❓ 2. Что такое AES? Почему именно AES-256?

**AES** (Advanced Encryption Standard) — симметричный блочный шифр.  
Принят как стандарт NIST в 2001 году.

| Версия | Размер ключа | Раундов |
|--------|------------|--------|
| AES-128 | 128 бит | 10 |
| AES-192 | 192 бит | 12 |
| AES-256 | 256 бит | 14 |

**Почему 256**: максимальная из стандартных длин ключа.  
AES-128 взломать перебором нереально при современных компьютерах,  
AES-256 — запас прочности на будущее (квантовые компьютеры).

---

### ❓ 3. Что такое симметричное шифрование? Чем отличается от асимметричного?

| | Симметричное | Асимметричное |
|--|-------------|--------------|
| Ключи | Один ключ и для шифрования и для расшифровки | Открытый ключ (шифровать) + закрытый (расшифровать) |
| Скорость | Быстрое | Медленное |
| Примеры | AES, ChaCha20, DES | RSA, ECC, ElGamal |
| Применение | Шифрование данных | Обмен ключами, подписи |

> В программе: AES-256 (симметричное) — быстро шифрует файлы любого размера.

---

### ❓ 4. Что такое CBC и зачем нужен IV?

**CBC** (Cipher Block Chaining) — режим работы блочного шифра.

```
Шифрование:
  C[0] = Encrypt(P[0] XOR IV)
  C[1] = Encrypt(P[1] XOR C[0])
  C[i] = Encrypt(P[i] XOR C[i-1])

Расшифровка:
  P[0] = Decrypt(C[0]) XOR IV
  P[i] = Decrypt(C[i]) XOR C[i-1]
```

**Проблема без CBC** (ECB режим):  
Одинаковые блоки открытого текста → одинаковые блоки шифротекста → видны паттерны.

**IV** (Initialization Vector):  
- Случайное число, используется для первого блока
- Разный IV → разный шифротекст даже для одинаковых данных
- Не секретный, хранится вместе с данными

---

### ❓ 5. Что такое хеш-функция? Какие у неё свойства?

**Хеш-функция**: отображение произвольных данных → фиксированная длина.

**Свойства SHA-256:**
1. **Детерминированность**: одни данные → всегда один хеш
2. **Однонаправленность**: из хеша нельзя восстановить данные
3. **Устойчивость к коллизиям**: найти два разных входа с одним хешем — вычислительно невозможно
4. **Лавинный эффект**: изменение 1 бита входа → ~50% бит хеша меняется

SHA-256 выдаёт 256 бит = 32 байта = 64 hex-символа.

---

### ❓ 6. Что такое аппаратный отпечаток (Hardware Fingerprint)?

Уникальный идентификатор компьютера из набора параметров железа/ОС.

**В нашей реализации:**
```
Fingerprint = SHA-256(username + hostname + RAM_MB)
```

**Зачем**: привязать лицензию к конкретной машине.  
Если скопировать программу на другой компьютер — отпечаток изменится → ключ недействителен.

**Проблема**: пользователь переустановил ОС, сменил RAM → потеряет лицензию.  
Поэтому коммерческие системы используют более стабильные параметры (MAC-адрес, серийник HDD).

---

### ❓ 7. Как генерируется лицензионный ключ?

```
key_hash = SHA-256(MASTER_SECRET | hardware_fingerprint | filename)
key_formatted = первые 16 hex символов в формате XXXX-XXXX-XXXX-XXXX
```

**Особенности:**
- Ключ уникален для каждого **файла** и каждого **компьютера**
- MASTER_SECRET — константа в коде (в реальности должна быть секретной)
- Верификация: вычислить ожидаемый ключ и сравнить с введённым

---

### ❓ 8. Как хранится зашифрованный файл?

Формат `.drm` файла:
```
Base64(
  [16 байт IV] || [AES-256-CBC шифротекст]
)
```

**Почему Base64**: позволяет хранить бинарные данные как текст, удобно для передачи.

Расшифровка:
1. Base64-декодировать
2. Первые 16 байт = IV
3. Остаток = шифротекст
4. AES-CBC-Decrypt(ключ, IV, шифротекст)

---

### ❓ 9. Что такое лицензирование ПО? Виды лицензий?

| Вид | Описание |
|-----|---------|
| Perpetual (бессрочная) | Купил один раз — пользуешься всегда |
| Subscription (подписка) | Платишь ежемесячно/ежегодно |
| Trial (триал) | Ограниченное время или функции бесплатно |
| Per-device | Привязка к конкретному устройству |
| Per-user | Привязка к пользователю (не к устройству) |
| Volume | Одна лицензия на N устройств |

### ❓ 10. Что такое Obsidium / WinLicense?

Инструменты для защиты Windows-приложений (.exe) от:
- Реверс-инжиниринга (обфускация, виртуализация кода)
- Несанкционированного копирования (привязка к железу)
- Нелицензионного использования (проверка ключей)

**Отличие от нашей реализации:**
- Они защищают исполняемые файлы (exe)
- Используют более сложные механизмы (VM-обфускация, anti-debug)
- Мы защищаем **данные** (файлы), а не сам код

---

### ❓ 11. Что такое триал-версия программы и как её реализовать?

**Триал** — ограниченная версия программы:
- По времени: работает 30 дней, потом требует ключ
- По функциям: базовые функции бесплатно, расширенные — платно
- По количеству запусков

**Как реализовать:**
```
1. Записать дату первого запуска в зашифрованный файл
2. При каждом запуске: если (now - first_run) > 30 дней → показать форму покупки
3. Защита: файл с датой шифруется, скрывается, привязан к железу
```

### ❓ 12. Что такое PKCS#7 padding?

Блочный шифр работает только с блоками фиксированной длины (16 байт для AES).  
Если данные не кратны 16 байтам — нужно дополнить.

**PKCS#7**: дополнить байтами, каждый из которых равен числу добавленных байт.

```
Если не хватает 3 байта: добавить [0x03, 0x03, 0x03]
Если не хватает 5 байт:  добавить [0x05, 0x05, 0x05, 0x05, 0x05]
```

При расшифровке: прочитать последний байт → столько байт отрезать.

---

### ❓ 13. Можно ли взломать AES-256?

**Теоретически**: перебор 2^256 ключей — физически невозможно.  
2^256 ≈ 10^77, атомов во вселенной ≈ 10^80.

**Практически уязвимости:**
- Слабый пароль → атака по словарю (поэтому нужны требования к паролям)
- Утечка мастер-секрета из кода (hardcoded secret)
- Side-channel атаки (измерение времени, потребления энергии)
- Ошибки реализации

---

### ❓ 14. Чем отличается шифрование от обфускации?

| | Шифрование | Обфускация |
|--|-----------|-----------|
| Обратимость | Да (при наличии ключа) | Часто да, но сложнее |
| Математическая основа | Строгая | Нет |
| Цель | Конфиденциальность | Затруднить анализ |
| Примеры | AES, RSA | Base64 "шифрование", переименование переменных |

> Base64 — это **не шифрование**! Это кодирование (обратимое без ключа).

---

### ❓ 15. Какие недостатки у нашей DRM-системы?

1. **MASTER_SECRET в коде**: при декомпиляции кода секрет виден
2. **Простой fingerprint**: изменение RAM или имени пользователя ломает лицензию
3. **Нет защиты от снятия дампа памяти**: после расшифровки данные в RAM
4. **Нет серверной валидации**: нельзя отозвать лицензию
5. **Просмотрщик показывает только текст**: бинарные файлы (PDF, DOCX) не отображаются правильно
